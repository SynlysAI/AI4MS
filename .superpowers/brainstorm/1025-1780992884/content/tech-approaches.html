AI4MS 前端架构方案对比

三个完整技术组合，选择一个方向

A

Vite SPA · shadcn/ui · Zustand 推荐

React 18 + Vite + Tailwind CSS + shadcn/ui + Framer Motion + Zustand + React Router v7

优势

  • shadcn/ui 提供 Radix 级无障碍组件，同时完全可控样式，适合深色主题定制
  • Zustand 极简状态管理，比 Context 性能好，比 Redux 代码少
  • Vite 开发体验极快，HMR 秒级
  • 纯 SPA，部署简单（FastAPI 直接托管 dist/）

注意

  • 无 SSR，SEO 不重要（门户不面向搜索引擎）
  • shadcn/ui 需手动引入组件，初始搭建稍慢
B

Next.js · Radix · 全栈前端

Next.js 15 + Tailwind CSS + Radix UI + Framer Motion + Next Auth + Server Actions

优势

  • SSR/SSG 支持，首屏加载快
  • App Router 文件系统路由，约定优于配置
  • Server Actions 可以直接在组件中写后端逻辑

注意

  • 门户无 SEO 需求，SSR 是额外复杂度
  • 需要 Node.js 服务器，不能简单托管在 FastAPI 静态文件目录
  • Server Actions 与已有 FastAPI 后端功能重叠
C

Vite SPA · 全自定义组件 · 极简依赖

React 18 + Vite + Tailwind CSS + Framer Motion + Zustand，所有 UI 组件手写

优势

  • 最少依赖，bundle 最小
  • 100% 设计自由，不依赖任何组件库风格

注意

  • Modal、Dropdown、Dialog、Toast 等常见交互需从零写
  • 无障碍性需自行处理
  • 开发效率低于有组件库支撑的方案
